# COM230 · Semana 5 · Conjuntos, mapas e organização em pacotes

Explicações e exercícios autorais baseados nas fontes consultadas em 02/11/2026. A análise integral de livros, vídeos e lives permanece pendente; confira os status abaixo.

## Síntese

Set representa unicidade; Map associa cada chave a um valor, permitindo valores repetidos.

Implementações hash e em árvore diferem em ordem, requisitos e desempenho.

Pacotes organizam nomes e acesso e devem ser coerentes com compilação e arquivos.

## Objetivos

- Escolher HashSet, TreeSet, HashMap e TreeMap.
- Usar igualdade, hashing e ordenação coerentes.
- Organizar pacotes e aplicar operações chave–valor.

## Unicidade e associações

HashSet usa igualdade e hash para identificar elementos e não garante ordem de iteração. TreeSet mantém ordem natural ou fornecida por Comparator; comparação zero determina equivalência para a estrutura ordenada.

HashMap associa chaves únicas a valores. Repetir put na mesma chave substitui o valor anterior. TreeMap ordena pelas chaves. Map não estende Collection; keySet, values e entrySet oferecem visões para trabalhar com suas partes.

## equals e hashCode

Objetos iguais por equals devem ter o mesmo hashCode. O inverso é falso: hashes iguais podem corresponder a objetos diferentes. Estruturas hash tratam colisões, que não são prova de igualdade.

Evite modificar campos usados na igualdade, hash ou comparação enquanto o objeto está na estrutura. A posição calculada ao inserir pode deixar de corresponder ao estado novo. Prefira chaves imutáveis ou controle cuidadosamente remoção e reinserção.

## Implementações e pacotes

HashMap e HashSet favorecem operações esperadas rápidas quando o hashing é adequado. TreeMap e TreeSet atendem quando ordenação e consultas por faixa importam. Map como interface não impõe uma tabela hash.

HashMap permite chave e valores null; Hashtable não aceita null. TreeMap com ordem natural não aceita chave null; um Comparator específico pode alterar isso. Métodos sincronizados isolados não tornam automaticamente uma sequência composta atômica.

package define um espaço de nomes e ajuda a controlar acesso. import disponibiliza nomes de tipos de outros pacotes no arquivo. Classes públicas, nomes de arquivos e diretórios devem corresponder à organização de compilação.

## Programa completo: unicidade e contagem

O Set elimina repetição e o Map conta ocorrências. TreeSet e TreeMap deixam a saída ordenada: [Ana, Bia] e {Ana=2, Bia=1}. A segunda entrada Ana incrementa o valor da chave existente.

entrySet permite percorrer pares tipados sem casts de raw types. Use esse padrão para ligar chave e valor durante a travessia.

```java
import java.util.*;
public class Main {
    public static void main(String[] args) {
        List<String> nomes = Arrays.asList("Bia", "Ana", "Ana");
        Set<String> unicos = new TreeSet<>(nomes);
        Map<String, Integer> frequencias = new TreeMap<>();
        for (String nome : nomes) {
            frequencias.put(nome, frequencias.getOrDefault(nome, 0) + 1);
        }
        System.out.println(unicos);
        System.out.println(frequencias);
        for (Map.Entry<String, Integer> e : frequencias.entrySet()) {
            System.out.println(e.getKey() + " -> " + e.getValue());
        }
    }
}
```

## Prática comentada

### 1. Após put(7,"A") e put(7,"B") em mapa vazio, qual tamanho e valor?

1. Há uma única chave, 7.
2. O segundo put substitui o valor; get(7) retorna B.
3. Tamanho=1. Valores iguais em chaves diferentes são permitidos.

### 2. Escolha estrutura para nomes únicos em ordem alfabética.

1. TreeSet<String> oferece unicidade e ordem natural de Strings.
2. HashSet não garante ordem.
3. Se precisar ignorar caixa ou acentos, defina Comparator e sua noção de equivalência com cuidado.

### 3. Uma chave mutável parece desaparecer do HashMap após alteração. Explique.

1. Se hashCode muda, a busca pode procurar em outra posição.
2. O objeto pode continuar armazenado com localização incompatível com seu novo estado.
3. Use chave imutável ou remova antes de modificar e reinsira controladamente.

## Erro comum

Colisão de hash não significa igualdade. Map proíbe chaves duplicadas, não valores repetidos.

## Flashcards

- **Set versus List?** Unicidade versus sequência posicional com repetições.
- **Map permite valores repetidos?** Sim; as chaves são únicas, mas os valores podem se repetir.
- **put em chave existente?** Substitui valor e não aumenta a quantidade de chaves.
- **HashMap garante ordem?** Não. TreeMap ordena as chaves.
- **Contrato de hashCode?** Objetos iguais por equals devem ter mesmo hash; colisão não implica igualdade.
- **Pacote Java?** Espaço de nomes que organiza tipos e participa do controle de acesso.

## Questões autorais

### 1. put(1,"A"), put(1,"B"), put(2,"B") em mapa vazio deixam tamanho:

A. 2
B. 3
C. 1
D. 0

**Gabarito:** A. Há duas chaves; a segunda inserção substitui o valor da chave 1.

### 2. Qual mantém elementos únicos ordenados?

A. TreeSet.
B. ArrayList sempre.
C. HashMap de qualquer tipo.
D. InputStream.

**Gabarito:** A. TreeSet combina semântica de conjunto e ordenação.

### 3. Mesmo hashCode significa:

A. Possível colisão; equals ainda importa.
B. Objetos sempre iguais.
C. Mesma identidade obrigatória.
D. Objetos proibidos na tabela.

**Gabarito:** A. A função hash pode mapear objetos diferentes ao mesmo código.

### 4. Map é subinterface de Collection?

A. Não.
B. Sim, estende List.
C. Sim, estende Set.
D. Sim, somente TreeMap.

**Gabarito:** A. Map possui hierarquia própria, embora suas visões sejam coleções.
