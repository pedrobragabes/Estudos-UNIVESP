# COM230 · Semana 3 · Herança, polimorfismo, interfaces e classes abstratas

Explicações e exercícios autorais baseados nas fontes consultadas em 02/11/2026. A análise integral de livros, vídeos e lives permanece pendente; confira os status abaixo.

## Síntese

Herança deve representar especialização e preservar o contrato do tipo base.

Polimorfismo permite referência comum para objetos de implementações diferentes.

Interfaces definem contratos; classes abstratas podem compartilhar estado e implementação.

## Objetivos

- Modelar especialização e contratos.
- Distinguir sobrescrita de sobrecarga.
- Prever despacho dinâmico e reconhecer limites de conversão.

## Especialização e composição

Uma classe Java pode ter uma superclasse direta e implementar várias interfaces. Use herança quando o objeto puder cumprir as expectativas do tipo base. A mera vontade de reutilizar código não justifica qualquer hierarquia.

Se uma impressora usa um documento, ela não é um documento. Associação ou composição representa melhor essa relação. Campos private da superclasse não se tornam diretamente acessíveis pela subclasse; use operações do contrato.

## Sobrescrita e sobrecarga

Sobrescrita especializa método de instância herdado com assinatura compatível. A implementação executada depende do objeto em execução. @Override permite que o compilador confira a intenção.

Sobrecarga oferece mesmo nome com parâmetros diferentes; a seleção da assinatura ocorre em compilação. Métodos static e campos não participam do despacho dinâmico da mesma forma que métodos de instância sobrescritos.

## Interface e classe abstrata

Interfaces permitem uma capacidade comum em classes de hierarquias distintas. Classes abstratas podem compartilhar estado e comportamento, deixando partes para tipos concretos. Não se instanciam diretamente tipos abstratos.

Uma referência de interface limita as operações visíveis ao contrato declarado. Java 8 permite métodos default e static em interfaces; isso não equivale a oferecer estado de instância de uma superclasse.

## Programa completo: comportamento selecionado pelo objeto

A saída é PDF: notas e CSV: notas. O laço usa Exportavel, mas cada instância fornece produzir. super inicializa o título da classe base.

Um cast não transforma o objeto em outra classe: apenas muda a forma de tratar a referência. Conversões incompatíveis podem causar ClassCastException.

```java
public class Main {
    interface Exportavel { String produzir(); }
    static abstract class Relatorio implements Exportavel {
        private final String titulo;
        Relatorio(String titulo) { this.titulo = titulo; }
        String getTitulo() { return titulo; }
    }
    static class Pdf extends Relatorio {
        Pdf(String t) { super(t); }
        @Override public String produzir() { return "PDF: " + getTitulo(); }
    }
    static class Csv extends Relatorio {
        Csv(String t) { super(t); }
        @Override public String produzir() { return "CSV: " + getTitulo(); }
    }
    public static void main(String[] args) {
        Exportavel[] xs = {new Pdf("notas"), new Csv("notas")};
        for (Exportavel x : xs) System.out.println(x.produzir());
    }
}
```

## Prática comentada

### 1. Animal a=new Cachorro(); a.emitirSom(); Qual implementação sobrescrita executa?

1. O tipo declarado é Animal e o objeto real é Cachorro.
2. O despacho escolhe a implementação de Cachorro.
3. O tipo declarado ainda define a validade da operação em compilação.

### 2. receber(Pdf) e receber(Exportavel) na mesma classe são sobrescrita?

1. São sobrecarga: os parâmetros diferem.
2. A assinatura é selecionada em compilação.
3. Sobrescrita exige método herdado e assinatura compatível.

### 3. Impressora deve estender Documento porque usa um documento?

1. Não: usar não significa ser uma especialização.
2. Modele uma relação de uso ou composição.
3. Defina uma interface se diferentes documentos oferecerem um contrato comum.

## Erro comum

Sobrecarga e sobrescrita são mecanismos diferentes. Cast não altera a classe real do objeto.

## Flashcards

- **extends?** Declara superclasse; classes Java têm herança simples direta.
- **implements?** Declara atendimento a uma ou mais interfaces.
- **Sobrescrita?** Especializa método de instância herdado com assinatura compatível.
- **Sobrecarga?** Mesmo nome, listas de parâmetros diferentes.
- **Instanciar abstrata diretamente?** Não; exige implementação concreta.
- **O que escolhe o método sobrescrito executado?** O objeto real em tempo de execução.

## Questões autorais

### 1. Exportavel e=new Csv("notas"); e.produzir() retorna:

A. CSV: notas
B. PDF: notas
C. Exportavel: notas
D. Referência de interface é proibida.

**Gabarito:** A. O objeto Csv fornece a implementação do método.

### 2. Mesmo nome com parâmetros diferentes é:

A. Sobrecarga.
B. Sobrescrita sempre.
C. Serialização.
D. Ocultação de pacote.

**Gabarito:** A. A sobrecarga muda a lista de parâmetros; a sobrescrita especializa método herdado.

### 3. Uma classe pode:

A. Estender uma classe e implementar várias interfaces.
B. Estender diretamente várias classes.
C. Instanciar abstrata sem implementação.
D. Trocar sua classe real usando super.

**Gabarito:** A. Java combina herança simples de classes e múltiplas interfaces.

### 4. @Override ajuda a:

A. Conferir a sobrescrita ou implementação pretendida.
B. Criar instância automaticamente.
C. Tornar método static.
D. Impedir toda herança.

**Gabarito:** A. O compilador verifica a correspondência do método com um contrato herdado.
