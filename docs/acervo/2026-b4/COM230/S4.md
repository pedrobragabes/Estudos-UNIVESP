# COM230 · Semana 4 · Generics e coleções em Java

Explicações e exercícios autorais baseados nas fontes consultadas em 02/11/2026. A análise integral de livros, vídeos e lives permanece pendente; confira os status abaixo.

## Síntese

Generics reutiliza código com relações de tipos verificáveis em compilação.

List representa sequência com posições e repetições; implementações têm custos distintos.

Iteradores e algoritmos utilitários fornecem operações padronizadas.

## Objetivos

- Declarar classes e métodos genéricos.
- Distinguir Collection, List, Iterator, ListIterator e Collections.
- Escolher operações e implementações tipadas.

## Parâmetros e limites

Caixa<T> parametriza uma classe; um método genérico declara <T> antes do retorno. A relação de tipos reduz casts e revela incompatibilidades cedo. Uma raw List enfraquece a verificação e pode adiar ClassCastException para execução.

Generics usa tipos de referência: List<Integer>, não List<int>. Não é possível criar new T() diretamente. Boa parte das informações genéricas é tratada por apagamento de tipos; não se deve supor geração de uma classe distinta por argumento.

## Invariância

Integer estende Number, mas List<Integer> não é List<Number>. Se fosse, alguém poderia adicionar Double na lista de inteiros. Esse raciocínio explica a restrição apresentada nos slides.

Como complemento autoral, List<? extends Number> permite ler números de listas com tipos mais específicos, sem inserir Number arbitrário. List<? super Integer> permite inserir Integer, mas sua leitura geral é Object. Escolha o curinga conforme as operações exigidas.

## Contratos e desempenho

Collection é interface geral; List acrescenta sequência posicional. ArrayList usa vetor redimensionável e favorece acesso por índice. LinkedList é encadeada: acesso por índice percorre nós, e inserir não é sempre O(1) quando localizar a posição faz parte da operação.

Collections é classe utilitária, diferente de Collection. Iterator percorre e pode remover pelo seu contrato. ListIterator acrescenta percurso em ambas as direções e operações de lista. Modificação estrutural externa durante for-each pode invalidar a travessia.

## Programa completo

O método primeiro preserva o tipo do elemento. A lista é ordenada e remove pares pelo próprio iterador. A saída é 1 e [1, 3]. Adicionar uma String nessa List<Integer> falharia em compilação.

iterator.remove é chamado depois de next. Não o substitua por remoção externa da lista dentro do mesmo for-each.

```java
import java.util.*;
public class Main {
    static <T> T primeiro(List<T> itens) {
        if (itens.isEmpty()) throw new IllegalArgumentException("Lista vazia");
        return itens.get(0);
    }
    public static void main(String[] args) {
        List<Integer> xs = new ArrayList<>(Arrays.asList(3, 2, 1));
        Collections.sort(xs);
        System.out.println(primeiro(xs));
        Iterator<Integer> it = xs.iterator();
        while (it.hasNext()) { if (it.next() % 2 == 0) it.remove(); }
        System.out.println(xs);
    }
}
```

## Conversões, listas de tamanho fixo e sobrecarga

Coleções genéricas usam tipos de referência: List<Integer>, não List<int>. Autoboxing converte int em Integer em contextos adequados; unboxing faz o inverso e pode lançar NullPointerException se a referência for null. Isso não torna os dois tipos idênticos nem permite comparar qualquer objeto com == para igualdade de valor.

Arrays.asList cria uma lista de tamanho fixo apoiada no array recebido: set pode alterar elementos, mas add e remove estruturais não são suportados. Para uma lista expansível independente, passe o resultado ao construtor de ArrayList. Atenção também a List<Integer>.remove: remove(1) escolhe o índice inteiro; remove(Integer.valueOf(1)) escolhe a primeira ocorrência do valor 1.

## Filas, pilhas e algoritmos de Collections

Queue descreve operações como offer, poll e peek; as duas últimas retornam null quando a fila está vazia nas implementações usuais que não admitem null. PriorityQueue remove segundo prioridade definida pela ordem natural ou comparador. Sua iteração não promete uma sequência globalmente ordenada: para obter os valores por prioridade, remova repetidamente com poll.

Stack é a classe histórica de pilha estudada no capítulo. Como complemento de uso, Deque também permite push, pop e peek para a disciplina LIFO. Algoritmos de Collections operam sobre coleções: sort ordena, reverse inverte e shuffle embaralha. A busca binária exige ordenação compatível com o comparador usado na busca. Alterar a ordem de uma lista pode afetar outras referências para o mesmo objeto.

## Prática comentada

### 1. Por que List<Integer> não pode ser List<Number>?

1. List<Number> permite adicionar Double.
2. Isso violaria o tipo de uma lista de Integer compartilhada.
3. Use curingas de forma coerente com as operações necessárias.

### 2. Declare uma caixa genérica sem cast não verificado.

1. class Caixa<T> { private T valor; void set(T v){valor=v;} T get(){return valor;} }
2. Instancie Caixa<String> e armazene String.
3. Não use new T(): o parâmetro não oferece um construtor automaticamente.

### 3. Diferencie Collection e Collections.

1. Collection é interface de coleção.
2. Collections é classe com métodos utilitários.
3. List e Set estendem Collection; Map tem hierarquia própria.

### 4. Uma List<Integer> contém [8,1,5]. Compare remove(1), remove(Integer.valueOf(1)) e uma remoção em Arrays.asList.

1. Em cópias independentes da lista expansível, remove(1) remove o elemento no índice 1, que vale 1; remove(Integer.valueOf(1)) procura o valor 1. Neste exemplo os resultados coincidem, embora os critérios sejam diferentes.
2. Para evidenciar a diferença, use [1,8,5]: remove(1) deixa [1,5], enquanto remove(Integer.valueOf(1)) deixa [8,5].
3. Uma remoção estrutural na lista de Arrays.asList lança UnsupportedOperationException; crie uma ArrayList se precisar alterar o tamanho.

## Erro comum

ArrayList<Integer> pode ser List<Integer>; isso não torna List<Integer> uma List<Number>.

## Flashcards

- **Método genérico?** Declara <T> antes do retorno: static <T> T identidade(T x).
- **Pode usar int como argumento de tipo?** Não; use Integer ou outro tipo de referência.
- **List<Integer> é List<Number>?** Não; tipos genéricos são invariantes.
- **Collection versus Collections?** Interface versus classe utilitária de algoritmos.
- **Contrato de List?** Sequência posicional, geralmente com repetições.
- **Remoção durante Iterator?** Use iterator.remove após next quando a implementação suportar.

## Questões autorais

### 1. Qual declaração é válida?

A. List<Integer> xs = new ArrayList<>();
B. List<int> xs = new ArrayList<>();
C. List<Integer> xs = new List<>();
D. ArrayList<int> xs = new ArrayList<>();

**Gabarito:** A. Parâmetros de tipo são referências; List é interface e precisa de implementação.

### 2. Collections.sort usa:

A. Classe utilitária de algoritmos.
B. Construtor de Collection.
C. Serialização.
D. Socket.

**Gabarito:** A. Collections fornece métodos estáticos sobre coleções.

### 3. ArrayList:

A. Tem acesso eficiente por índice e pode deslocar elementos ao inserir.
B. Tem toda inserção O(1) no pior caso.
C. Proíbe repetições.
D. É um mapa de chaves.

**Gabarito:** A. Vetor redimensionável favorece índice; inserções intermediárias deslocam valores.

### 4. Uma raw List com tipos misturados pode:

A. Adiar erro de cast para execução.
B. Garantir segurança genérica superior.
C. Converter Integer em String automaticamente.
D. Impedir toda compilação.

**Gabarito:** A. Parâmetros de tipo tornam muitas incompatibilidades detectáveis em compilação.
